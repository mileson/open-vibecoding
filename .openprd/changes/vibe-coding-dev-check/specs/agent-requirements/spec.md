## 新增需求

### 需求：Vibe Coding 自动化三连：dev-check 自动重构、图标自动匹配、拼图证据入流
OpenPrd 三项 Vibe Coding 自动化能力不足：1) dev-check 超行提醒停留在后续建议表格，用户不知如何处理，价值鸡肋；2) 开发新功能时图标最佳实践路由几乎从不自动触发（415 个图标相关会话仅 1 次真实接入图标库）；3) 拼图/网格对齐证据板真实触发率低，证据图不在对话流中可视化，AI 自我审查作用未发挥。

#### 场景：主流程成功
- **当** PM 打开终端或让 Agent 运行 openprd guide，看到 7 步流程和当前位置，按提示进入下一步
- **则** 在 openprd 自身仓库通过单元测试与 standards/quality/run verify；用 Codex CLI 在本地跑一个桌面任务实测新流程效果并留下证据。

#### 场景：边界情况保持可见
- **当** 工作区还没有任何需求版本时 guide 显示第 1 步并给出起步动作
- **则** 产品应保持该情况明确可见，以支持实现和验证

#### 场景：失败模式得到处理
- **当** 方向图片文件缺失时导入跳过该方向并提示，不中断其他方向导入
- **则** 产品应提供有边界且可评审的结果
