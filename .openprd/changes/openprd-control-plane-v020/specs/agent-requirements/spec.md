## 新增需求

### 需求：OpenPrd 可解释项目控制平面与跨工具上下文升级
统一项目事实、并发运行态和上下文编译，降低 token、延迟、错误目标与长期维护成本

#### 场景：主流程成功
- **当** Agent 进入已有项目，Adapter 识别运行环境，Context Compiler 基于 lane/task/revision 在预算内生成 Capsule 或 Delta
- **则** 全量单元、集成、并发、迁移、回滚、性能和三平台契约测试通过

#### 场景：边界情况保持可见
- **当** 同一 session ID 在多个工作区有线索时不语义猜测，返回候选和安全阻断
- **则** 产品应保持该情况明确可见，以支持实现和验证

#### 场景：失败模式得到处理
- **当** expectedRevision 不一致时返回 OPENPRD_REVISION_CONFLICT，不覆盖新状态
- **则** 产品应提供有边界且可评审的结果
