# Open VibeCoding 0.4.1

为已有产品设计新界面时，先理解项目风格，再生成和复核效果图。即使只需要一个弹窗、一张图、不写代码，也适用。

- 新增内部设计上下文能力：主动查看实际界面、截图、样式与组件，把参考传入生图，交付前自查；交互设计、效果图评审和视觉实现共同复用。
- 新增内部用户可见内容边界能力：隔离制作过程、实现说明和内部规则；生成前区分工作指令与可见文字，交付前检查实际结果并修正源头，保留必要业务反馈。
- 修复安装器以菜单短文案覆盖完整场景说明的问题；效果图入口同时支持单张提案和多方向比较。
- 纳入已确认的竞品增长分析、重要变化跟踪、资源使用权益与最小资源原则。
- 纳入研发三阶段与独立的复杂度、重复代码、测试有效性检查指引；外部检查工具按需接入，不默认安装。

本次为 GitHub 源码版本。已有源码安装可拉取本版本，再使用项目已配置的 CLI 更新集成；各项目客户端、Hook 和自定义说明保持各自配置。

## English

New UI should fit the existing product. Agents inspect the target interface and components before generating even a single mockup, pass actual references into generation, and compare the result before delivery.

A shared content-boundary capability keeps internal production rules and implementation commentary out of user-facing artifacts while preserving useful business feedback. It checks the actual delivered result, not just source text.

This release separates full skill discovery descriptions from concise menu labels. It also includes competitor growth and change tracking, resource entitlement and efficiency guidance, and composable code quality checks. External quality tools remain optional. This is a GitHub source release.
