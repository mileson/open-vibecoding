# Agent 自主 HTML 审查界面

## 责任边界

- Open VibeCoding 只通过 AGENTS 与 skills 注入判断原则和质量合同。
- Agent 自行理解任务、决定是否需要 HTML，并负责内容组织、页面设计、实现、验证和交付。
- 不要新增一个由 Open VibeCoding 根据关键词、分数或任务状态自动渲染通用页面的机制。
- 现有 `review.html`、质量报告、测试报告和学习阅读器继续承担各自固定流程职责，不自动覆盖任务专属审查需求。

## 何时重新判断

至少在以下边界重新判断一次“聊天是否足以支持用户审查”：

1. 任务刚进入，且不同方向会明显改变结果时。
2. 分析已经形成关键证据，需要用户共同判断时。
3. 实现与验证完成，准备让用户验收时。
4. 准备发布、发送、写日历、批量修改或执行其他高影响动作时。

HTML 不是任务完成仪式。真正触发点是下一个需要用户核查、比较、选择、纠错或验收的审查边界。

如果本轮交付包含只有用户或负责人才能完成的选择、批准或纠错，最终交付本身就是人类审查节点。Agent 自己将任务归为“直接分析”、L0/L1/L2 或只读分析，不构成豁免；只有用户或宿主明确禁止新增文件，才按无写入边界处理并说明理由。

## 强制触发条件

只要存在人类审查节点并命中以下任一条件，除非用户明确不要 HTML，或已经有能够完成同等核查、比较与反馈的任务专属审查界面，否则 Agent 必须制作并验证任务专属 HTML：

- 需要比较 8 个及以上对象、方案、状态、时间点或版本，并逐项呈现状态、依据、冲突、未知项或待决策内容。
- 用户需要对多个对象逐条批准、拒绝、选择、标注或填写原因，并保留可逆审查状态。
- 证据包含音频、视频、波形、时间线、多组截图或可交互原始数据，必须在来源上下文中查看才能判断。
- 复杂测试、Eval、回归、失败分类或发布候选矩阵，将直接成为发布、发送、日历写入、批量变更或其他高影响操作的输入。
- 交付物需要搜索、筛选、排序、分类切换、分页、章节导航或长期反复阅读，聊天无法保持必要结构。

这里的数量门槛是最低可预测边界，不是完整关键词分类。命中时，Markdown/CSV 可以作为数据源、明细附件或导出格式，但不能替代主要 HTML 审查界面；固定 `review.html`、质量报告、测试报告和学习阅读器也不会自动构成任务专属豁免。

## Agent 判断信号

未命中强制触发条件时，以下信号仍要求 Agent 结合用户判断成本主动决定是否制作 HTML，而不是等待用户索要：

- 少于 8 个对象，但对应关系已经难以在聊天中核查。
- 事实存在冲突、不确定项或 Agent 推断，需要让用户直接看到依据和边界。
- 审查需要对比、筛选、播放、标注或结构化反馈，轻量表达不能有效承载。

## 不应触发

- 简单问答、单一事实、短状态、单一动作或信息量很低的结果。
- HTML 只会把聊天内容换一种排版，没有提升核查、比较或反馈效率。
- 用户要的是封面、图标、插画、海报或其他图片资产；这些按生图路由处理。
- 未命中强制触发条件，且已有更合适的轻量表达，例如短表格、解释型 SVG、单张视觉证据板或直接文件链接。
- 用户明确要求不要 HTML、用户或宿主明确禁止新增文件，或已有任务专属界面能够完成同等核查、比较与反馈；豁免时在交付说明里简短记录理由。
- 自动化无人值守任务没有人类审查节点；此时按自动化 runbook 保存必要证据，不主动打开页面。

## 页面质量合同

Agent 制作任务专属 HTML 时，按本次审查需要选择下面的能力，不要机械堆满：

- 内容采用结论先行的总分总：推荐结论与待决策问题 → 按重要性展开理由、业务案例和细节 → 当前决定与下一步；每节先说结论。能用案例加深理解时优先业务案例，假设明确标注，不冒充真实效果。
- 明确区分可验证事实、Agent 推断、未知项和仍需人工判断的内容。
- 保留原始证据、来源路径、时间点、文件、测试命令或数据口径。
- 多对象比较保持同一尺度、同一字段和清晰对应关系；多媒体证据提供来源上下文，不只展示裁剪片段。
- 需要逐条审核时提供可逆状态、原因和备注；需要复用时保存状态并支持结构化导出。
- 只在有实际价值时加入播放、筛选、搜索、排序、标注、章节导航或 JSON/Markdown 导出。
- 使用当前用户能理解的语言，并在移动端和桌面端保持可读；遵守项目已有视觉与 i18n 结构。
- 在最终回复中给出可点击的绝对路径，并说明页面已完成哪些静态或运行态验证。
- 清除 starter、模板和示例中的所有无来源占位内容；页面里的对象、数字、结论和交互都必须能追溯到当前任务证据或明确标注的 Agent 推断。

HTML 评审页固定提供“复制评审结果给 AI”的反馈交接入口，使用 [评审反馈交接](review-handoff.md) 与其独立组件；统一按钮、左侧图标和成功/警告反馈，复制当前最新选择及填写内容，不用初始默认值代替用户决定。组件不限定正文布局，不触发发送或外部执行。

## 证据与完成边界

- HTML 能证明的是“审查材料已经可查看”，不能单独证明功能、设备、浏览器、生产环境或外部系统已经成功。
- 静态语法、文件存在或页面打开不等于交互和媒体链路已经验证；按风险补最小运行态检查。
- 页面内结论必须与原始证据一致；无法验证的内容保持未知，不用 `0`、成功状态或确定语气填空。
- 如果用户反馈改变了判断，更新同一审查产物或产生清晰版本，不要让旧页面继续被误认为当前结论。
- 命中强制条件后，没有可点击的任务专属 `.html` 绝对路径与验证说明，或页面仍是 starter/占位内容时，不得把该审查节点标记完成。
