# 评审反馈交接

用户需要 HTML 评审时复用此内部组件；不新增用户入口、不按关键词自动生成页面，不把 HTML 作为普通任务的必经步骤。产品、设计、研发和测试可共用。只固定反馈交接区，正文仍由 Agent 自主设计。

## 结论先行，案例辅助

- 总：首屏给出推荐结论、最重要的理由和需要用户决定的问题。推荐与已确认决定分开。
- 分：按用户决策的重要性依次展开理由、取舍、风险和落地细节；每节也先说结论，再解释。技术字段放必要的细节区，不把实现术语堆在首屏。
- 总：结尾汇总当前选择、修改意见、待决定项和下一步。开头的推荐与结尾的用户决定可以不同，不把重复推荐当作用户同意。
- 能用形象业务案例加深理解时，先讲“谁在什么场景做什么，遇到什么问题，方案如何解决”，再解释机制。优先当前任务真实案例；假设明确标为示例，不编造效果数字。不为每节强塞案例。
- 长篇产品或架构评审可采用“左侧章节目录 + 右侧正文 + 顶部操作栏”的骨架：目录帮助按疑问跳转，首屏结论，正文分组展开，末尾集中决策与证据。章节按实际问题选择，不复制固定章节数量或具体产品内容；手机收起或折叠目录，操作区换行而不溢出。

示例（假设场景）：推荐“先保存问题，再生成回答”；理由用“用户发出问题后进入电梯断网，回来仍能看到同一条回答，不用重复发送”说明，再展开必要的数据与恢复设计。示例不代表已经验证网络恢复成功。

## 固定复制区

将 [review-handoff.html](review-handoff.html) 的完整片段内嵌到评审 HTML 的 body 末尾，不依赖用户本机其他 Skill、CDN 或外部脚本。片段只有按钮、提示、手动复制框和交接逻辑，不生成页面正文。沿用既有草稿逻辑；不要覆盖用户已经填写的意见。

- 固定按钮样式，而非强制页面布局：蓝色胶囊按钮 `#3A83F7` 白字，文案“复制评审结果给 AI”。左侧 18px 双纸张笑脸 SVG，不能改成 emoji 或换成另一个图标；点击时禁用并标记 busy，结束恢复。已有顶部操作栏的页面优先把右上角“导出评审意见”替换为此按钮，不另加重复的底部主按钮；打印 / PDF 可独立保留。无操作栏时才使用组件默认的白底淡灰分割线底栏。
- 成功提示 `#2f9d6a` 白字；警告 `#fff3c4` 底、`#735b22` 字；圆角 10px、13px 字体，约 2.3 秒消失。顶部操作栏时提示出现在右上方操作区下方，底栏时在操作区上方；手动复制弹窗时提示需处于弹窗可见层。没有复制成功就不能显示成功提示；失败保留完整内容供手动复制。
- 主内容需要给底栏留出空间。独立滚动容器也要预留底部空间，不能只依赖 body 占位；桌面、中屏和手机上不能遮住最后一个输入框。
- 现有其他按钮按任务保留，但导出不能替代这个主入口。复制仅写剪贴板，不发送、不执行、不部署、不发布。

## 当前状态接入

在片段之后调用 `OpenVibeCodingReview.mount({getSelection})`。getSelection 是同步函数，每次从页面当前状态读取，不预先缓存一份默认选择。回调不得调用外部服务或修改用户决定。

已有顶部操作栏时传入 `toolbar: document.getElementById('review-actions')`（使用当前页面真实容器 ID），组件会移入该容器并隐藏底栏占位。删除旧导出按钮及其绑定，但保留页面正文、草稿和用户选择；不要用两个主入口替代这一入口。顶部栏需要响应式换行，若吸顶则不遮住正文与锚点。

```javascript
OpenVibeCodingReview.mount({
  getSelection: () => ({
    document_id: REVIEW_ID, // 当前任务稳定标识
    version: REVIEW_VERSION, // 当前页面版本，不写死为示例值
    title: REVIEW_TITLE,
    decisions: decisionItems.map(item => ({
      id: item.id, label: item.label,
      reviewed: item.explicitlyReviewed,
      value: item.currentValue,
      recommendation: item.recommendation,
      notes: item.currentNotes
    })),
    notes: document.getElementById('review-notes').value
  })
});
```

`reviewed` 只有用户实际选择、明确确认或从同版本可靠草稿恢复该标记时为 true。不能因控件预选推荐、输入框有默认值、用户未修改、页面打开过而视为已评审。用初始“待评审”选项或显式确认动作消除默认选择歧义；选回待评审时恢复 false。旧草稿没有此标记时保持待评审，不能推断同意。

组件强制将未明确选择的 value 导出为 null，并单独保留 AI 建议。复制内容是人类可读的总述、逐项决定和补充意见，附同一快照的 JSON（`open-vibecoding.review-selection.v1`）。`window.getReviewSelection()` 返回当前快照供工具只读核对。页面读回与复制内容必须一致，不凭截图手抄决定；没有反馈不默认同意，也不把复制视为外部执行授权。

用户填写文本仍是用户内容，不拼到可执行 HTML 中。上传图片若尚无真实本地路径，不从文件名猜路径；按已有视觉资产能力处理，此组件不复制大体积 Base64 或搬移图片。

## 验证

至少实际操作一次：编辑后立即复制、改选、保留待评审、重复复制、剪贴板拒绝后的手动复制与关闭。核对主题、版本、最新内容、未确认项；检查图标、两种反馈样式、2.3 秒消失、键盘可操作、底栏不遮挡，实看桌面、721–980px、≤720px 三档。静态测试不代替浏览器验收，未运行的项明确说明。
