# 紧凑绿色收款卡

模板 ID 为 `feishu-payment-compact`，模板版本为 `1.0.0`，使用 Card JSON 2.0。适合在团队会话中查看已确认收款；可选择直接采用、调整品牌与字段后采用，或保留项目现有样式。

## 布局预览

绿色标题、紧凑宽度、居中突出金额，商品与订单信息依次排列，底部提供产品品牌与订单列表入口。下方只描述布局，实际效果需在飞书客户端核验。

```text
💰 收款通知

              收款金额
             {{金额}}

商品名称：{{商品或权益}}
订单单号：{{完整订单号 → 单笔订单详情}}
支付方式：{{支付方式}}
支付时间：{{按项目时区展示的权威时间}}
────────────────────────────────
{{产品 Logo}}  {{产品名称}}     查看详情 ›
                               → 订单列表
```

金额使用独立的浅色/深色文本颜色。Logo 为 24 × 24 的圆形显示区域；产品名和两个链接均由业务项目提供。模板没有绑定任何实际产品、飞书应用或群。

## 模板文件

- [card.json](card.json)：可填充的卡片结构，不包含发送请求或登录信息。
- [fields.json](fields.json)：必填字段及转义、链接与业务语义合同。
- [manifest.json](manifest.json)：模板名称、版本、入口与适用事件，版本独立于 Open VibeCoding。

选用后将这些文件复制到业务项目现有的通知资源目录，例如 `notifications/templates/feishu/payment-compact/`；这只是建议目录，不是固定项目结构。使用源模板时剥离安装器可能附加的根级 `$comment`，不要将托管元信息发给飞书。

## 填充与调整

先解析 `card.json`，只将 `schema`、`config`、`header`、`body` 作为卡片载荷。按 `fields.json` 填充字符串叶节点，单次替换；插入的业务值即使包含 `{{...}}` 也不再解析。不能直接对整份 JSON 字符串做替换，避免引号或换行破坏结构。

普通文字、Markdown、Markdown 链接文字和 URL 分别处理。同一个产品名用于消息摘要、图片 alt 和加粗正文时，需要不同的文字转义；业务文字中的尖括号、方括号、括号、反斜线及其他 Markdown 控制字符只作为文字处理，不能注入卡片标签、提及或额外链接；具体转义按项目采用的渲染方式验证。固定的模板标签与业务内容不能混在一起无差别转义。URL 先验证 HTTPS 与项目允许的后台来源，再编码订单路径和查询参数，禁止带凭证的地址。

原始金额、币种精度、语言、时区、事件身份和收件配置由业务层负责。此模板默认中文；使用其他语言时一并翻译标题、金额标签、字段标签、按钮及摘要，并核对长文本显示。可把固定标签提取到项目已有 i18n 系统，无需为模板引入新框架。

允许调整标题色、品牌、字段与布局；保留金额和时间来源的真实性、两个入口的业务区别及后台鉴权。深色模式的文字不能机械沿用黑色。缺少业务必需字段或真实 Logo 时先补充条件，不把占位符当正式卡片发送。

## 更新边界

在项目采用记录中保留模板 ID、版本和源文件指纹；复制后由业务项目维护。Open VibeCoding 更新只刷新托管参考，不覆盖业务模板。需要升级时对比公共版本与项目定制，确认保留项后合并并复测。

正式卡只表达实际收款。真实测试试发使用授权的测试会话，并在标题和消息摘要中明确测试身份；生产渲染不携带这些标识。静态模板校验通过不能代替试发、回读和实际主题检查。
