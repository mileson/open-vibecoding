# 飞书接入与项目运行边界

## Agent 配置阶段

优先复用宿主已有的飞书 CLI 或连接；没有时才推荐官方工具并按用户授权安装。具体命令、版本和权限以执行时工具帮助及官方文档为准，不在模板里固定个人机器路径或复制一套厂商 Skill。

1. 用工具的只读配置与身份检查确认可用应用、profile 和授权状态；不要读取原始凭证配置，也不要把默认应用用于所有项目。
2. 选定对应项目用途的应用与目标会话。在支持该参数的 lark-cli 中，业务调用显式指定已核实的 `--profile` 和 `--as user|bot`；应用身份与用户身份分别核验。机器人未获权限时不能靠用户重新登录解决，也不切换无关应用绕过错误。
3. 仅申请当前发送、图片上传及所选回读方式需要的权限。应用发消息和上传图片可使用应用授权；不能一概要求用户登录或开放全部权限。先确认机器人可访问目标会话，再做授权范围内的最小验证。
4. 正式产品 Logo 由实际发送应用上传并取得图片标识，不沿用另一应用的图片标识。没有 Logo 时说明待补条件或与用户确认文字品牌变体，不能用相似产品图标冒充。
5. 采用宿主飞书卡片工具时先读该工具要求的卡片创建说明，再将本模板作为样式与字段输入。如果工具要求专用构建步骤，按步骤生成兼容载荷，不绕过它直接发送参考 JSON。
6. 真实试发前明确接收会话、身份和内容；配置检查不构成发送授权。发送后按返回的消息标识回读，核对字段和链接；所需读取权限缺失时如实记录，不虚报内容已经验证。

## 业务项目运行阶段

项目后端或已有通知服务负责自动发送，不依赖开发者电脑上的 CLI 持续运行。应用机器人是本模板的参考通道，采用该通道时根据项目应用类型配置凭证获取方式；不得把用户 CLI 登录令牌复制到服务器当永久凭证。

已有合法通知网关或其他飞书通道能满足需求时可以继续使用，但须独立核实卡片兼容性、目标权限、回执与重试行为，不把不同通道的能力视为等价。

项目内配置应用身份、收件目标、环境、时区、语言、模板版本及凭证的安全引用；公共模板不保存具体值。日志只记录必要的事件键、结果类别、重试状态和回执，不记录 token、App Secret、完整请求头或支付原始载荷。
