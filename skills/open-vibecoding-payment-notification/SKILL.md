# 收款通知规范与可选模板

横向最佳实践的独立内部能力，供研发、交互与测试按场景复用。根据用户想在收款后获得通知的意图选择，不按固定关键词派发，不要求用户主动调用。规范、样式与项目接入分别维护；Open VibeCoding 不运行财务服务，也不保存用户的通知身份。

## 先理解项目，再让用户选择

- 查看目标项目的支付确认、订单、权益提交和已有通知实现，区分真实收款、订阅续费、退款及授权冻结等事件。只讨论方案时保持只读，不因提供模板而修改业务或发送消息。
- 先复用现有通道和模板。需要飞书卡片时展示 [紧凑绿色收款卡](references/templates/feishu/payment-compact/v1/README.md) 的布局、适用条件和可调整项，提供“采用模板 / 调整后采用 / 保留现有样式”选择；用户已明确选定时不重复询问。
- 首个模板适用于团队查看已确认收款。它是可选的 Card 2.0 样式，不是所有通知必须采用的界面，也不是默认发送目标。退款、支付失败等事件应单独定义状态与文案，不能改金额后复用绿色成功卡冒充收款。
- 本能力只分发轻量方法、字段合同与模板资源，不附带财务网关、SDK、数据库、机器人账号或常驻 worker。缺少飞书工具时按 `$open-vibecoding-tool-selection` 引导可选接入；配置方法见 [飞书接入](references/feishu-setup.md)。

## 通知依赖真实业务结果

- 以服务端已验签支付回调或主动查单的明确成功结果为依据，核对商户、订单、金额和币种。订单创建、拉起支付、客户端成功提示、未核实回调不能作为正式收款依据。
- 按项目实际业务确认订单和必要权益已提交，才产生收款通知事件；无权益交付的业务不强行增加权益系统。不能把仍待处理的交付描述成已经完成。
- 通知失败不回滚已确认支付和已提交权益。优先复用项目已有持久化队列或 outbox；确有需要才在原事务内增加待发送事件，不默认建立新服务。
- 用稳定业务事件键去重，包含必要的项目、环境、交易及事件类型；订阅续费等独立交易不能被误合并。保留发送状态、重试边界与可查询的回执。收到超时不等于发送失败，先核对原请求状态，避免盲目重发；外部接口去重不能代替项目持久化去重，也不承诺跨系统绝对只送达一次。
- 保存原币种金额与精度，不用浮点计算改写支付事实、不自行换汇、不固定两位小数；符号可能有歧义时显示币种代码。时间取权威支付时间，只有确认时间时明确标为“支付确认时间”，不能用通知时间替代；时区与语言按目标项目配置。
- 卡片只包含收件人完成任务需要的业务字段。凭证、用户联系方式、平台用户标识、原始支付载荷和调试堆栈不进入卡片；订单标识与后台链接也需符合收件范围，链接继续执行权限校验。

## 选定后复制到目标项目

- 用户确定目标项目及模板后，将选定版本复制到该项目现有的通知资源目录；没有目录时采用小而清晰的项目目录，不复制整套公共 Skill 或其他厂商资源。只导入所选模板，不自动启用通知。
- 模板版本与工具版本独立。采用记录只保留模板 ID、版本和源文件指纹，可放在项目现有配置或模板旁的元信息中；不为此生成 PRD/change/tasks。不要将项目定制写回安装目录中的托管参考文件。
- 复制 JSON 时剥离安装器附加的根级 `$comment`，业务卡片只使用模板定义的 `schema`、`config`、`header`、`body`。填充在解析后的对象上按位置进行，区分普通文字、Markdown、图片标识与 URL；禁止对整个 JSON 文本直接替换变量。
- 按 [字段合同](references/templates/feishu/payment-compact/v1/fields.json) 映射业务字段。原始金额、时区、收件目标、应用身份和密钥引用留在业务层，不塞进卡片模板。已有多语言项目同步维护支持的语言。
- 后续公共模板更新先比较源版本与项目定制差异，只合并用户需要的改进；不得覆盖已复制并定制的业务模板。初始化或更新 Open VibeCoding 只更新其托管参考，不修改项目通知代码、凭证或线上行为。

## 验证与交付

按 [验收案例](references/verification.md) 检查字段、重复事件、异常恢复和实际渲染。真实试发需目标和发送授权明确，复用用户指定的测试会话与应用；上线启用不能由“模板已选择”推导。

分别报告模板静态校验、字段映射、通道连接、实际试发回读及生产事件是否已验证。没有发过卡就不能说飞书效果或送达已验证；有实际视觉审查时复用 `$open-vibecoding-visual-evidence-delivery` 展示截图。卡片里的业务文案沿用 `$open-vibecoding-public-content-boundary`，开发过程和规则只留在说明文档与代码中。
