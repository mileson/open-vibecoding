# 视觉层级与精修

交互设计域的内部子能力，由效果图生成、界面实现和评审按场景复用，不要求用户主动调用。按用户目标和实际画面判断，不用固定关键词匹配；只处理能改善本次任务的问题，不把以下维度变成每次必跑的流程或评分表。

## 从界面用途判断

- 先复用 `$open-vibecoding-design-context` 的目标界面、实际参考、组件与样式约束。已有产品默认继承设计语言；明确重设计或从零设计时再探索风格。
- 确认用户打开页面要看懂什么、找到什么、完成什么，以及主要信息、操作和辅助说明。每项建议说明它改善的具体问题，不能只写“更高级、更简洁”。
- 以实际画面和内容观察问题，优先检查结构、分组、对齐与层级，再决定装饰是否需要调整；这表示判断优先级，不规定固定编辑顺序。
- 只要求分析或评审时不改产品；已授权实现时在原范围内调整。参考视频的改版转场不能直接当成产品动效或可用性证据。

## 按问题选择精修维度

| 需要判断的方面 | 具体方法与边界 |
| --- | --- |
| 信息层级 | 区分核心内容、关键动作、当前状态和辅助说明；用字号、字重、位置、空间与明暗建立先后。避免所有卡片、徽标和按钮同等抢眼，也不把所有页面简化为唯一焦点。 |
| 对齐与空间 | 同类组件的图标、标题、说明、数字和操作各自对齐，核对基线与视觉重心；用间距表达组内关联和组间区别。优先沿用项目的间距与控件尺寸体系，不把参考图的像素数写成通用标准。 |
| 色彩含义 | 保留品牌语言，让强调色支持操作、状态或分类；同一对象跨区域保持颜色含义一致。状态同时提供文字或图形线索，避免只靠颜色区分。暗色、中性或低饱和均不是默认审美答案。 |
| 字体与数字 | 沿用合适的项目或系统字体，明确标题、正文、指标与辅助文本的角色；检查长文案、多语言、数字位数和单位变化。不能为差异化盲目换字体，也不能通过过小、过细或过灰来制造精致感。 |
| 图标与素材 | 功能图标保持家族、线宽、尺寸和视觉重量一致，按需复用 `$open-vibecoding-icon-system`；功能图标、品牌标识和装饰插画分别判断，不把 emoji 或线性图标一概禁用或强制使用。 |
| 表面与细节 | 用必要的背景差异、边框、圆角、阴影表达区域、选中和可操作状态；检查重复装饰是否分散注意力。允许局部品牌记忆点，但不能挤压关键内容、遮挡操作或暗示不存在的交互。 |
| 标题与反馈 | 标题交代当前任务、对象或时间范围，比较数据明确基准；是否保留问候语按用途决定。复用 `$open-vibecoding-public-content-boundary`，将设计规则留在工作上下文，保留用户需要的操作反馈。 |
| 图表与动效 | 先确认指标、单位、时间范围、系列和比较关系，再选择图形；保留真实数值及含义，不为好看改数据、平滑掉异常或加入无含义的镜像。动效帮助理解状态与连续关系，检查等待、打断和减少动态效果需求，不能把宣传转场照搬进产品。 |

## 检查实际结果

- 对照同一任务、视口、内容与状态，区分确定的视觉问题、可用性阻碍与主观风格建议。局部调整只检查相关区域和受影响的相邻状态，不机械扩大为三方向重设计。
- 在实际消费尺寸检查可读性、可发现性和操作空间，按目标平台检查窄屏、文本增长、焦点、选中、禁用、加载与失败等相关状态；对比度或可访问性未实际测量时，不宣称已达标。
- 需要精确定位时复用 `$open-vibecoding-visual-localization` 的网格与局部放大，完成后检查无网格结果。静态稿只能证明当前画面，不能代替操作验证。
- 效果图沿用 `$open-vibecoding-visual-direction-review` 的原图、拼图、版本与 final 约定；实际界面沿用 `$open-vibecoding-visual-evidence-delivery` 展示截图。没有实际运行或覆盖不到的部分如实说明。
- 交付说明本次改善了什么、如何核对及剩余缺口；不强制生成审美报告、PRD、change 或 tasks。需要具体示例时读取 [场景案例](references/scenarios.md)。
