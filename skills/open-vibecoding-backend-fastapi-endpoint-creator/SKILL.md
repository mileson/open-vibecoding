# 实现 FastAPI 端点

用于在已有 FastAPI 服务中新增或扩展明确的 HTTP 端点。规划、契约评审和影响分析保持只读。

1. **对齐契约。** 从接口约定、调用方及现有测试确认方法、完整路径、输入、响应字段与状态码、错误格式和数据可见范围。没有明确写下的细节先从同类端点和现有调用方补齐。关键权限或数据访问范围仍缺乏依据时，指出具体缺口，暂停依赖该决定的写入并继续独立工作。
2. **找到实际接入点。** 从应用入口或应用工厂沿路由注册关系，读一个同类端点和相关测试。确认 URL 前缀和依赖的继承关系、依赖及锁定版本、请求响应模型、异常映射、业务层、数据访问和事务归属。涉及第三方版本或 API 且本地证据不足时，按 `$open-vibecoding-benchmark-router` 核实。
3. **按项目惯例实现。** 复用满足契约的模型、依赖和业务函数，按需新增路由、请求与响应模型以及实际需要的业务或数据访问代码。通过现有机制挂载路由，核对最终路径、方法、鉴权和响应契约。使用项目真实的分层与同步或异步调用方式。对读写、分页或事务有影响时查阅 [端点检查清单](references/endpoint-checklist.md)。
4. **从正常应用入口验证。** 按项目方式启动测试应用或使用已有 fixture，通过完整 URL 检查成功响应、输入校验及适用的未授权和越权行为。写接口验证实际数据变化和失败时的状态。按契约核对 OpenAPI 与调用方依赖的字段。交付时说明路径、改动、实际验证结果和缺口。

按已授权的功能实现范围推进。没有业务依据时，沿用项目既有的数据保留、文档可见性和兼容策略。
