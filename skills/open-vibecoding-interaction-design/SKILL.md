# 交互设计

交互设计覆盖用户如何找到内容、理解选项、完成任务、收到反馈和从错误中恢复。视觉设计是其中的感知层。用户可以直接描述问题；不要求先提供线框图或选择工具。

## 工作方法

1. 接收产品判断、用户任务和现有界面事实；缺少底层目标或范围时，先回到 `$open-vibecoding-product-diagnosis`，不要用界面细节掩盖问题。
2. 定义信息组织和任务路径：入口、导航、页面或状态之间的关系，以及核心路径的结束条件。
3. 定义行为合同：每个关键动作的前置条件、默认状态、加载、成功、失败、撤销、权限与空状态。技术约束只在确实影响用户行为时进入说明。
4. 明确界面与信息框架：重要信息先后顺序、控件选择、标签、可发现性和决策点。检查用户是否能看懂每个选择，并知道自己是否走在正确方向。
5. 大界面仍需比较方案时调用 `$open-vibecoding-visual-direction-review`；已选方向或参考图进入实现时调用 `$open-vibecoding-frontend-design`。已有截图时先继承现有视觉 DNA，原型与实际产品分别验收。
6. 用 `$open-vibecoding-test-strategy` 选择可用性任务观察、状态覆盖、视觉比对、可访问性和真实运行态验证。用户说“看起来不错”不等于能完成任务。

## 最小交接

留下用户任务、导航/流程、状态与异常、关键页面与内容、视觉约束、原型或实现引用、未验证假设及测试任务。结构、框架与表现可以并行探索，但上层方案定稿前要复核其依赖的产品判断。
