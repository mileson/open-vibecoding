# 外部工具发现与接入

Open VibeCoding 只提供场景判断与接入提醒。厂商 Skill、查询实现、SDK、凭证及常驻服务不作为这些场景的包内依赖；不创建统一插件管理系统，不批量安装候选工具。

## 按任务选，不按品牌派发

- 先看当前宿主实际暴露的工具、项目已有连接和用户选择。有查询工具不等于连接成功；在授权范围内用最小只读查询验证目标与权限。不要读取原始凭证配置来做能力发现。
- 产品转化或留存问题需要产品使用数据；崩溃和错误问题需要异常数据。工具是否适合取决于数据覆盖与问题，不以用户提到某个词自动派发。
- 已有 MCP、CLI、报表或导出数据足够时直接使用。只有独立的复杂方法确有复用价值时，才推荐外部 Skill；仅在它实际可用且任务需要时加载。
- 没有合适能力时解释它能补什么、成本及权限影响，并给官方入口；用户同意后才安装配置。支持用户不接入并继续使用现有材料，不强制替换已有供应商。

## 分清接入缺口

竞品研究按问题选择商店与市场数据、社媒内容、搜索数据或实际产品体验工具。已有页面、导出表格和授权连接够用就复用；付费数据平台、云手机和多 Agent 环境只是可选手段，不作为默认依赖。不同供应商估算口径需分别核验；不复制教程里的价格、模型型号或反爬承诺。需要新的接入时先核验当前官方说明、费用与权限，再由用户决定，不默认购买账号或代理。

| 当前情况 | 合适的下一步 |
| --- | --- |
| 没有查询工具 | 推荐与任务相符的可选工具，确认是否需要接入 |
| 工具存在但连接或权限失败 | 说明真实错误，核实最小只读权限；不报成没有数据 |
| 已连接但产品映射不明 | 确认当前产品对应的远端项目、环境；不遍历无关产品 |
| 查询可用但应用未上报或未发布 | 单独说明应用接入与发布需求，不视为配置查询工具的附带授权 |
| 查询成功且结果为空 | 核对范围、采集覆盖、近期活动和上报延迟后，给有限结论 |

项目绑定留在各产品自己的现有配置或私有记录中，按需包含数据源、远端项目标识、环境、时区及版本线索，不强制创建新配置文件。凭证仅使用安全存储引用；按宿主规则从凭证管理能力获取最小字段，不把密钥、个人项目列表或服务器信息写进公共 Skill。

安装配置查询工具、修改应用采集、发布带采集的新版本是不同动作，不相互隐含授权。接入成功只报告已实际验证的环节，不笼统声称“生产监控已完成”。

## 异常查询工具示例

产品已用 Rollbar 或用户选择它时，可以参考 [Rollbar 官方 MCP 接入说明](https://docs.rollbar.com/docs/mcp-server-setup)：支持多项目配置，查询可使用只读权限，修改问题需要额外写权限。它只是可选示例，不是默认依赖，也不意味着宿主一定提供该连接。

## 代码质量工具

研发质量检查可分别使用 Crapper、Dryer、Mutator，独立子能力为 `$open-vibecoding-code-complexity-review`、`$open-vibecoding-code-duplication-review`、`$open-vibecoding-test-strength-review`。安装与调用方式见已安装 `$open-vibecoding-code-quality` 的 `references/quality-tools.md`；优先复用核实过的隔离环境，缺失时按授权接入，不在所有业务项目批量安装。工具能运行、报告成功、实际覆盖目标和业务验收通过分别判断。

实际接入时按当前官方文档与宿主能力核验安装、配置和兼容性，不复制过时版本、个人安装路径或未经验证的命令。按项目外部技术调研规则先查本地，不足时使用 Context7；不可用或覆盖不足再补官方一手资料并说明缺口。
