# 工具能力选择

先看用户目标、当前宿主真实可用能力和已有任务资源；`capabilities` 可发现产品场景，`doctor` 可诊断安装状态，但两者不替 Agent 决策。

- 优先复用当前会话与项目已有的工具、窗口、服务和证据。不要因为能力存在就全部调用，也不要为一次任务创建并行重复环境。
- 图像、浏览器、画布、外部资料与代码工具各按其实际能力边界使用；不可用时说明缺口并选择安全降级，不假装已执行。
- 需要第三方 API、CLI 或 SDK 新用法时先核对本地证据，仍不足再按项目外部技术调研规则查一手资料。
- 选择只改变执行手段，不扩大用户授权；高影响外部动作、敏感信息和额外付费服务按宿主安全规则处理。

需要产品数据分析、线上异常查询或其他可选外部能力时，按需读 [外部工具发现与接入](references/optional-external-tools.md)。已有 MCP、CLI 或报表能完成任务就直接使用，不为了调用工具额外包装 Skill；外部工具缺失不影响其他场景。

输出工具选择理由只需足以解释影响和限制，不生成固定工具计划或上下文胶囊。
