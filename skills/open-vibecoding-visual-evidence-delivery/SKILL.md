# 视觉结果交付

用户需要直接看到界面最终是什么样。凡涉及界面视觉的审查、修改或复查，最终回复必须嵌入本轮实际运行截图，不等用户追加要求。纯代码、无界面逻辑和非视觉任务不因此启动浏览器。独立 reviewer 把截图交给主 Agent 后，主 Agent 仍负责向用户展示。

## 按场景交付

| 当前情况 | 最终回复展示什么 |
| --- | --- |
| 已有用户确认的效果图或参考 | 确认参考与最终实际界面；保持相同页面、状态、视口及合理缩放，说明无法一致的条件 |
| 没有提供效果图 | 最终实际界面截图，说明页面和状态 |
| 小范围对齐、图标或文字修改 | 实际界面上下文与关键局部；需要说明变化时补充修改前后图 |
| 涉及多个关键状态 | 展示各个受影响状态的真实截图，可拼图但保留各张原图 |
| 只做评审，没有修改 | 当前被审查界面的实际截图，问题标注按需附加；不伪称已修复 |

## 截图与展示

- 复用本任务可安全操作的浏览器、应用或设备，确认运行版本已经加载本轮改动。截图后亲自查看，核对目标页面、状态、裁切与可读性。需要打码时保留布局，不泄漏账号、凭证和无关个人信息。
- 保留干净截图；红色网格、框选与局部图只作辅助，不覆盖原图。截图及比较图按项目现有设计证据位置保存并区分版本与状态，不为此生成 PRD、tasks 或固定报告。已有 `design/<scene>/vNNN/` 的确认参考沿用其 final 记录。
- 在最终回复正文直接嵌入宿主支持的图片或工具返回的 `chatEmbed`。本地图片使用绝对路径 Markdown 图片语法。只给文件路径、下载链接、工具输出或“已检查通过”的文字不算完成展示。多图可并列或拼图，同时能查看原图。
- 生成的效果图只能作为参考，不能充当实际运行截图。参考图和实际图明确标识角色，不把不同版本、不同状态或旧图冒充本轮结果。
- 工具、环境或权限不允许取得实际截图时，说明具体缺口与已检查范围，并标记视觉未验证；不得声称已完成视觉验收。无需为截图扩大生产操作权限、重复启动设备或安装重依赖。
- 截图证明界面呈现，不证明保存、支付、后台数据或媒体质量。业务结果仍按验收能力实际读回；两类证据不能相互替代。

收口前检查：用户是否能直接看到本轮实际界面？有确认参考时是否能比较？是否明确页面、状态和未验证边界？
