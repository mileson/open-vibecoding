# 图片框选与说明标注

内部增强能力，按任务需要由设计、研发、测试和内容场景组合，不新增用户必选入口。方法提炼自 screenshot-annotator；工具与合同随 Open VibeCoding 分发，不依赖个人 Skill 路径、偏好文件或本机字体路径。

先明确要告诉用户哪个动作、问题或结果。需要准确位置时用 `$open-vibecoding-visual-localization` 看原图、网格和局部图；标注始终画在无网格工作副本上。保留原图，已确认版本不覆盖；有隐私时从已验证的安全副本派生，网格和裁切也遵循同一隐私边界。

- 框住用户理解的完整操作单元，例如菜单的图标与文字、完整按钮或选中行。只圈实际目标，不连带相邻动作；确定必须包含及排除哪些内容，不能仅凭矩形合法认定准确。
- 标签说明动作或可见问题、结果。一条只说一件事，不把长段说明放进图。独立单点不编号，真实顺序用数字，并列或互斥入口用 A/B；不把页码当步骤。
- 优先红色实线圆角框，必要时按品牌选择同套颜色。标签与目标紧邻且归属清楚；字号按最终展示宽度检查，不把手机大字号套在密集桌面图上。
- 保护标题、按钮文字、星号、提示、数值及其他背景字形。OCR 可辅助提供文字区域，仍需目视补漏；标签、编号和框线不能压字。无安全位置时换锚点、缩短标签或拆图，不能移动准确的目标来迁就标签。

轻量框选与标签可用内置 CLI，计划与边界见 [标注合同](references/annotation-plan.md)：

```sh
open-vibecoding image-annotate --source /absolute/source.png --out /absolute/new-annotated.png --json-file /absolute/plan.json
```

输出包含实际框位、标签位置与 `awaiting_visual_review`。它只验证声明的几何关系，不自动识别目标或穷尽 OCR，也不保证字体与语义正确。完成后实际打开完整标注图、关键局部和最终显示尺寸；批量时另看总览。Agent 可报告自己已看图复核，不伪造用户或独立人工签核；脚本通过不能改写成视觉通过。

只改失败的框位、标签或字号，复用已确认部分。复杂箭头、批量排序、长图和教程文档按需选择当前可用专用工具；没有这些需求就不生成 Manifest、阅读图、审查页面或教程材料。新建、重绘或生成图像仍走原生生图能力，坐标标注使用确定性叠加工具。
