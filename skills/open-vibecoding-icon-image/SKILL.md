# 原生图标生成

先确认消费组件需要 `transparent-cutout` 还是 `opaque-full-bleed-tile`，实际尺寸和已有图标参考。使用当前宿主原生生图能力；在 Codex 按可用的 `$imagegen` 与工具合同执行，不写死某个模型 API 参数，不自动切换用户自有付费通道。没有原生能力时明确缺口，优先评估检索或 SVG 路径。

提示词明确：语义主体、用途与目标尺寸、产品气质、同家族参考、轮廓、色彩角色、材质、视角、光源、阴影和安全留白。单枚独立输出，避免 UI 截图、文字标签、展示卡片与画面内容器。先确定一枚代表性资产，再将其作为家族参考扩展；不要每张都随机换光源和材质。

透明资产优先请求原生透明背景，并实际检查 alpha；保留已正确的透明度。用户要求色键抠图或输出缺少可靠 alpha 时，生成与主体颜色明显分离的纯色背景，无渐变与背景纹理；先选背景色，再用 `$open-vibecoding-icon-cutout`。绿色可用但不是固定答案，绿色主体应选其他对比色。不要靠近白色的背景去抠白色主体，也不要将复杂摄影背景误当可自动色键去除。

Full-bleed 资产覆盖四边四角，不运行透明化；消费容器圆角、边框和阴影通常留在代码中。生成结果需检查主体是否完整、四角/边缘是否符合模式、是否有烘焙白边和不必要装饰。

查看原图与处理后图片，在浅色、深色和实际产品背景上检查光晕、缺口、残色、细线及半透明阴影。工具完成不代表视觉通过。项目使用的最终资产落到项目路径、接入消费组件并做成套小尺寸比较，不能只引用宿主生图缓存路径。可核验的参考与结果按需保留。
