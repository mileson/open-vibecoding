# 模块参照与接入检查

| 要搭建的骨架 | 先看哪些文件 | 根据什么决定新增文件 |
| --- | --- | --- |
| 可复用选择组件 | 同一 Target 中的选择组件及一个真实调用点 | 调用点决定参数、状态和选择结果如何传递。只有多个调用方要配置相同行为时再考虑配置对象。 |
| 业务页面或流程 | 邻近业务模块、导航入口及依赖装配位置 | 根据已有的职责划分选择界面、状态和业务依赖。只有页面需要独立业务规则或数据访问时才加对应文件。 |

例如，在与现有选择器同一 Target 中添加标签选择器，先读调用处如何提供选项和接收结果，再按同一方式暴露输入输出。如果现有视图直接接收选项和绑定，且新组件也只需要这两项，一个视图文件可能就够。若要搭建带加载与异常反馈的独立页面，先看邻近模块由哪一层持有状态和注入服务，再复用相同接入方式。

## 接入检查

- **文件归属**。确认项目通过 Xcode 工程、工程生成配置或 Swift Package 管理哪些源码和资源。只改项目指定的维护入口，并检查是否已自动纳入目标，避免新增重复的文件引用。
- **依赖与样式**。沿用参考模块的导航、依赖装配和颜色资源。需要文案时，确认语言范围、查找表和资源 bundle 与真实消费方一致。
- **可编译性**。检查导入、可见性、可用版本与调用点。编译选中目标只能证明编译范围内的结果。资源查找、导航和界面行为按交付范围从真实入口验证。
