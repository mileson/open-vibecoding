# 故障定位与修复

先界定预期与实际、影响范围、触发条件和最近变化。复用现有日志、运行环境和最小复现；不要靠重复重启或重建碰运气。

- 把观察、候选根因和反证分开；沿数据与状态流追到可证实的失败点。无法确认时明确还缺什么证据。
- 用户只要求诊断时保持只读。要求修复时做最小有因果依据的改动，并增加能防止同类回归的验证。
- 修复时主动用 `$open-vibecoding-diagnostic-readiness` 检查再次发生能否继续定位，按需补强并读回诊断证据；不等用户再次提醒加日志。现有证据够用就复用，只读诊断不自动补代码。
- 真正需要运行态、媒体、小程序或视觉证据时使用对应验证能力；单个测试通过不代表所有用户路径已覆盖。
- 收口说明根因、改动、复测结果和剩余风险；不创建 PRD/change/tasks 作为故障记录。

如果调查显示是产品目标或交互结构问题，转 `$open-vibecoding-product-diagnosis` 或 `$open-vibecoding-interaction-design`，不要把症状只当代码错误处理。
