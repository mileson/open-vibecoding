# 图标获取与风格统筹

属于 Vibe Coding 增强，由交互设计和研发复用。新功能出现入口、按钮、导航或空态时，Agent 主动判断是否需要图标并补齐，不要求用户先去找素材。语义本身不需要图标或用户要求纯文字时省略。

先看项目已有图标包、资产、消费组件和目标尺寸，明确图标的角色：操作符号、第三方品牌标志、技术标志、功能插画或自己的产品标识。继承现有视觉语言；新产品根据目标用户、产品气质与界面密度建立图标家族。图标好看与能被认出要同时成立。

按缺口选择子能力，不要求逐个走完所有来源：

- 能通过现有图标家族或外部素材满足需求时，用 `$open-vibecoding-icon-source`；同组控件先沿用同一套图标。
- 需要独有、可编辑、可缩放的简单符号时，用 `$open-vibecoding-icon-svg`。
- 需要品牌化材质、立体物件或复杂插画时，用 `$open-vibecoding-icon-image`；按需复用 `$open-vibecoding-icon-cutout` 获取透明 PNG。

把实际需要的风格合同传给各子能力：语义、画布与光学尺寸、线宽、端点与圆角、描边/填充、色彩角色、留白；位图再加材质、视角、光照和阴影。共享一张代表性图标参考，而非每个图标独立发明风格。品牌 logo 保持识别与官方变体，通过容器尺寸与留白协调，不为统一而重绘第三方标志。

在真实消费尺寸和控件里检查一整组：轮廓辨识、视觉重量、主体大小、内留白、光学居中、明暗背景、选中/禁用状态以及相同槽位对齐。工具测得中心只是几何证据；必要时用 `visual-compare` 的 centering-board 或 alignment-board 检查视觉重心。导航小图标避免细碎纹理，功能插画不直接缩成 16px 操作图标。

交付已接入的资产和对应来源/许可、变体与消费位置。只在复用或后续对比有需要时保留简短素材映射与成套参考图；不生成固定 PRD/change/tasks。尚未下载、只有候选图或未在界面验证时说明状态，不把它们当成完成资产。
