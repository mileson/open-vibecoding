# 按需产品文档

涉及用户可见内容时，落实内部 `$open-vibecoding-public-content-boundary`：把制作过程、开发规则和实现解释隔离在成品之外；生成前区分可见文案与工作指令，交付前检查实际结果。保留必要业务反馈，用户明确要求时才在指定文档解释内部过程。

先确定读者要凭文档做什么：理解机会、比较方案、实施功能、验收结果或对外发布。选择能完成该任务的最小形式；用户指定格式时沿用指定格式，不默认套 PRD 模板。

- 事实、决定、建议和待确认项分别表达。引用研究、数据或竞品时保留来源与日期，避免把推断写成事实。
- 方案与评审说明采用结论先行的总分总，按重要性展开理由与细节，能用业务案例加深理解时优先案例；假设明确标注。用户要 HTML 评审时复用 `$open-vibecoding-harness` 的 `references/review-handoff.md`，提供统一的“复制评审结果给 AI”交接，而不把初始推荐当用户决定。
- 面向研发的说明聚焦用户行为、边界、异常和成功条件；已有代码足以表达的实现细节不重复抄写。
- 面向用户的文案说清能做什么、会发生什么、下一步是什么；已有 i18n 时同步所有支持语言。
- 文档是本次明确交付物或确需维护的活文档，不是 Agent 开工许可证。旧 `.open-vibecoding/` requirement、PRD、change、tasks 只读保留，不覆盖历史。

目标或证据仍不清楚时调用 `$open-vibecoding-product-diagnosis` 或 `$open-vibecoding-product-research`，只对真实歧义提出必要问题。

## 产品使用教程与发布分享

- 面向新手的产品使用教程，先给定位、适用场景与整体路线，再按需求展开入口、步骤、可见结果和故障处理；完整覆盖不等于重复表达，删除制作注释和只为组织素材而写的标题。
- 组合 `screenshot-annotator`，读取其 `references/product-tutorial-delivery.md`：每个核心场景配连贯仿真数据的真实运行截图与标注；设备预览图裁去无关外层界面，插画补充场景理解，不能替代真实界面。
- 首次创建对外教程时，发布阶段未知才询问内测还是正式开放；已有上下文直接沿用。内测文案带内测入口与教程链接，正式开放文案带已确认的使用入口与教程链接，均应用用户写作风格并以 `text` 代码块交付完整 URL。
- 对外分享交付包含可访问的教程链接及可直接复制的文案；用户指定公开阅读时执行并回读核验，不把单篇授权扩展到其他文档或公开编辑。
