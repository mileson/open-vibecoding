# 共用规则

## 用户与 Agent

- 先理解用户当前目标与授权范围。规划、分析、评审保持只读；实现、继续、修复等明确请求才进入写入。
- Agent 管理自己的上下文、计划和任务状态。Open VibeCoding 不生成 PRD、change、tasks 来替代 Agent 思考；历史 `.open-vibecoding/` 资料只读参考。
- 面向用户先讲结论、影响和下一步，少用内部状态、hook、schema、lane 等词。用户可见文案写清能做什么、会发生什么、失败后怎么办；非技术产品不暴露 API、模型、缓存或错误码。
- 修改用户可见文案前检查项目 i18n，并同步已有支持语言。按各语言产品习惯重写，不逐字翻译；在真实控件中检查截断、布局和辅助功能名称。
- 复杂比较可以用简洁表格或图示帮助理解，但不为简单事实生成页面或文件。用户明确要求文档时再作为交付物制作。

## 证据与风险

- 外部技术事实、公开仓库和最佳实践遵守 `$open-vibecoding-benchmark-router` 的本地优先、Context7 / DeepWiki 与一手证据规则。
- 选择与风险相称的验证。代码、测试与运行结果是默认事实来源；视觉参照及实现对比、媒体结果、外部动作读回等无法从代码重建的证据按需保留。
- UI 大改按交互与视觉决策成本评审方向；轻量微调不机械触发三方向。已有参考图时区分用户确认与 Agent 候选，实现后按需用 `visual-compare` 检查差异。
- 涉及凭证、账号或个人信息先用 `secrets-vault`，只取当前需要的最小字段，不输出完整密钥。
- 浏览器 Computer Use 优先在任务专用窗口；点击、输入、发送、删除、切换账号、支付等动作前核对窗口归属和目标。
- 小程序运行态验证依当前环境规则选用本地工具；没有实际运行证据时不声称已验证。真实媒体任务从最终媒体复测，不用纯文案检查代替。
- 发布、生产、支付、删除、批量写入等高影响动作遵守用户范围、真实权限与宿主安全规则；工具提示不代替授权。

## 资源与收口

- 优先复用现有进程、服务、浏览器和缓存，避免重复启动重资源；只清理本任务创建的资源。
- 代码改动后运行本任务最小足够验证，说明通过、失败、未验证及原因。`dev-check`、`doctor` 等诊断是建议，不是实现许可。
- 现有文档因本轮变化失真时同步更新；否则代码即默认实现说明，不为了留痕补文档。
- 修改 Skill/workflow 前先读取现状，按项目约定展示彩色 Mermaid 方案并取得确认。
