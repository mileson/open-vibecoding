# 验收与回归

从用户可观察的目标和改动风险倒推验证任务。先读取 `$open-vibecoding-test-strategy` 的“真实用户操作优先验证”：复用已有环境，以测试用户从真实入口完成受影响路径，并检查最终结果；局部测试和模拟响应只补充它们能证明的部分。

当前客户端实际提供可安全使用的 Computer Use 时优先亲自操作；网页稳定重复回归可使用 Playwright 等现有工具。不能仅凭宿主名称认定工具可用，也不能把真实场景等同于默认获准操作生产环境。没有界面的任务按其真实消费入口验证，不强开浏览器。

用户希望独立产品视角亲自检查运行界面的交互时，用 `$open-vibecoding-ui-interaction-review`；希望一并修复和复查时用 `$open-vibecoding-ui-review-and-repair`。普通验收不自动派发修复。

- 实际运行验证，区分通过、失败、未运行和无法验证；说明环境、版本、测试角色、真实操作、最终结果以及模拟或未覆盖的环节。成功提示不代替保存后重开、实际权益或最终文件等结果检查。
- 界面视觉任务落实 `$open-vibecoding-visual-evidence-delivery`，最终回复必须嵌入本轮实际截图；有确认参考时展示参考与实现，无参考时展示实际界面。媒体从最终媒体复测；外部动作读回实际结果。
- 对精细对齐、框选偏移或局部位置差异，主动用 `$open-vibecoding-visual-localization` 的网格和局部图核对；问题说明按需用 `$open-vibecoding-image-annotation`，同时检查无网格结果。不能从辅助图的坐标直接推断屏幕点击位置。
- 对失败先分析现有输出，不靠反复重启或清缓存硬重试。高风险缺口不能以“构建通过”替代。
- 故障修复或性能优化的验收按需复用 `$open-vibecoding-diagnostic-readiness`，实际读回新增或保留的诊断与耗时证据，验证能串联并取得；只要求验收时不借此修改代码。
- 输出可行动的验收结论与剩余风险。只有用户需要长期审查或复杂矩阵时才制作报告或界面，不自动生成任务文件。
