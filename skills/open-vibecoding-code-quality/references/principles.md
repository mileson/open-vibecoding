# 实现原则与主题覆盖

参考 [unclebob/ub-mode](https://github.com/unclebob/ub-mode/tree/57a8bdd28e45ed41900ace0bafa2ff76dd9ed70f)，以下为结合 Open VibeCoding 场景独立编写的中文执行指南。保留主题覆盖，不逐句复制原文；固定三个研发阶段，按任务范围确定每项工作的深度。

## 实现行为

| 原主题 | 中文执行提醒 |
| --- | --- |
| Laziness Protocol | 同一个业务决策维护一个权威来源，选择真正解决问题的最小改动。少写代码不等于省略必要处理。 |
| Foundational Thinking | 先理顺数据形状与状态归属，优先完成能减少后续返工的基础；并发写入会改变结果时检查共享状态是否必要。 |
| TDD | 先用失败测试刻画目标行为，核实失败原因，再最小实现；无法可靠测试时保留真实验证缺口，不造空断言。 |
| Redesign From First Principles | 新需求暴露旧边界不合适时，重新考虑合理结构，分块实现；不自动全面重写，也不无限叠补丁。 |
| Attack the Premise | 同一假设下两次修复仍过不了同一验证时，明确该假设并核对参与方、状态写入和责任归属。原文的 “Remove the assignment” 缺少具体上下文，这里按纠正错误归属理解，不当作无条件删除赋值语句的命令。 |
| Subtract Before You Add | 添加抽象、状态或分支前，先寻找能消除的冗余；保留真实兼容与失败恢复行为。 |
| Outcome-Oriented Execution | 以可检查的最终业务状态推进。开发中间态允许暂时不完整，但要有可恢复边界，不能将这种许可用于破坏运行中的业务。 |
| Build the Lever | 复杂或重复操作先核验一个单元，再形成工具；工具放入对应项目长期复用，成熟后再考虑跨项目提炼。 |
| Model the Domain | 用数据结构明确合法状态，业务术语复用项目已有词汇与命名；确有歧义才补术语说明，清晰局部代码不为架构形式拆散。 |
| Boundary Discipline | 外部输入进入系统时校验和转换，核心业务计算尽量与网络、存储等副作用分离。内部信任建立在已验证的边界上。 |
| Type System Discipline | 用合适类型减少非法组合，外部数据在边界解析；不以压制编译器错误掩盖状态问题。动态语言用等价的明确数据约束。 |
| Make Operations Idempotent | 对重试、重复提交、崩溃后恢复明确结果，避免重复扣款、发放或写入。核对幂等键、事务或已有机制是否真正覆盖业务操作。 |
| Separate Before Serializing Shared State | 能独立拥有的状态先隔离；必须共享时用结构约束写入者或原子更新，跨进程与分布式场景需核对真实并发边界。 |

## 整理质量

| 原主题 | 中文执行提醒 |
| --- | --- |
| Fix Root Causes | 从复现、日志和状态流证明原因，修复原因并复测；只压住报错或隐藏界面异常不足以证明已修好。 |
| Sequence Work into Verifiable Units | 每个小单元实现后及时验证，再进入下一个；由 Agent 自主拆解，不要求任务文档或状态机。 |
| Test Behavior, Not Implementation | 从调用者入口验证可观察结果，避免仅断言内部实现细节；必要时故意破坏行为，检查测试是否真的报警。 |
| Crapper | 独立复杂度检查能力；默认以 CRAP 小于 10 为改善目标，结合有效覆盖率分析分支，不能凭 case 数量机械拆分。 |
| Dryer | 独立重复代码检查能力；检查相似度大于等于 0.8 的候选，区分同一业务规则与碰巧结构相似。 |
| Mutator | 独立测试有效性能力；补重要未覆盖行为，分析存活变异、等价变异和无效变异；确认不可达及无外部使用后才删死代码。 |
| Refactoring | 固定现有行为，改善结构，再证明行为未变；计划内功能变化与纯重构分开说明。 |

## 工程收尾

| 原主题 | 中文执行提醒 |
| --- | --- |
| Keep a Log | 按用户明确取舍，不采用逐步记录与汇报；只交付关键结果和不可重建的必要证据。故障诊断日志属于产品能力，仍按诊断补强规则处理。 |
| Guard the Context Window | 主线程保留决策与证据摘要，按需读取长内容；任务拆分和委派遵守宿主约束，不为了摘要丢失错误、反证或未完成项。 |
| Worktree Cleanup | 名称反映问题或功能；核实提交、归属与使用状态后安全收尾，保留未完成和其他任务内容。 |
| Commit and Push | 在项目约定与授权内进行有序提交、主分支整合、推送和读回；检查未完成则如实交付，不为满足阶段名强制提交发布。 |

## 业务案例

用户要求修复“网络暂时断开后被显示成未登录”：先补断网后凭证仍保留、恢复后可重试的失败测试，核实失败点，再修改会话状态判断。随后检查错误分支是否重复、状态处理是否过度复杂，以及把重试条件反转后测试能否发现问题。最后从真实登录入口操作断网与恢复，展示实际状态，保留必要诊断信息，并完成已授权的 Git 收尾。

用户要求批量迁移多个项目的配置：先在一个有代表性的项目核对改动与读回，再形成可重复运行、能跳过冲突的项目工具；避免每次手动重写迁移脚本。工具与说明属于项目资产，运行流水不变成强制文档。
