# 最佳实践

这是五个执行能力域可共同调用的横向板块。提供有条件的默认建议，让 Agent 选择当前项目适合的实现；不是必经阶段，也不接管任务规划。

先读当前项目事实：平台与框架、锁定依赖、工具链/CI、最低部署版本、已有实现、发布与兼容约束。选择能改变本次判断的独立实践，读取其适用条件和验证方式。具体专项已有 `$open-vibecoding-ios-localization`；已融入各场景的方法见 [实践索引](references/practice-index.md)，按需读取负责该方法的能力，不复制其规范。其他主题可作为独立 Skill 和场景增量注册，不把所有平台说明灌入入口。

在条件满足的新增实现中优先已核实的官方现代方案。现有实现仍受支持时，不仅因年代较旧就要求整体迁移；有明确迁移目标时比较资源、调用行为、成本和验证能力。条件不足时说明具体限制及适合的兼容路径，不静默改工具链、提高最低系统版本或扩展改动范围。

实践条目说明推荐方案、适用前提、兼容/迁移边界、验证方式和来源。来源优先当前官方文档与本地类型定义；历史对话和经验用于发现问题，不单独证明通用结论。本地证据不足时沿用 `$open-vibecoding-benchmark-router` 的 Context7 / 官方证据规则，精确核实本轮需要的 API 与版本。

按场景和证据选择条目，不用关键词表或名称正则匹配。新增条目保持独立；需要组合时用目录 `uses` 描述复用关系。只在当前交接有需要时说明采纳的实践和例外，不要求生成技术方案、PRD/change/tasks 或留痕报告。
