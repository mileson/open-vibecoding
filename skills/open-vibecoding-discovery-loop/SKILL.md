# 持续调研

用户要求深挖项目、竞品或一个复杂问题时，先界定研究问题、来源和停止条件。Agent 自主选择阅读、搜索、核验与分析顺序；本 Skill 不创建任务状态机，也不把调研结果转为固定文档链。

## 场景

- `brownfield`：从现有代码和实际运行态查行为、缺口与风险。
- `reference`：调查参考项目，区分可迁移原则与不可照搬的实现。
- `requirement`：澄清用户问题、替代方案、约束、风险和成功信号。

若用户只要求分析，保持只读。需要外部技术事实或公开仓库架构时，遵循 `$open-vibecoding-benchmark-router` 的证据顺序。多来源材料注明来源、时间、权威性与未知项；不要把推断写成事实。

## 执行

1. 从用户目标提炼少量可回答的问题；相关代码、README、锁文件和现有证据优先。
2. 逐项核验关键假设，发现矛盾时回到原始来源，不用文档数量替代判断质量。
3. 需要长期阅读或多对象比较时，才保存证据索引或任务专属审查界面；普通调研直接在对话中总结。
4. 用户要求实现时，把已确认的改动目标交给 Agent 自主拆解并逐项执行；不生成 PRD、change 或 tasks 文件作为前置步骤。
5. 结论说明事实、推断、仍未知和下一步最有价值的验证。已有 `.open-vibecoding/discovery/` 资料只读参考，不自动续写旧状态。

是否使用 subagent 只由当前用户请求和宿主规则决定；本 Skill 不自动要求并行。
