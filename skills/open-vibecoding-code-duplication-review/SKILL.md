# 检查重复代码

内部研发能力，独立调用 [Dryer](https://github.com/unclebob/dryer)。先读取已安装的 `$open-vibecoding-code-quality` 下 `references/quality-tools.md`，核对语言、目标路径、安装与结果解释。

- 在项目根目录用已核实环境的 `python -m dryer --threshold 0.8 <目标路径>`。上游默认是 0.82，本能力显式采用 0.8；保留项目明确指定的其他阈值并说明差异。
- 变更范围外可能存在相同规则的调用方；按实际关联扩展到有关目录，避免只扫一个新文件就认定全项目无重复。
- 相似度是结构相似的线索，不保证业务语义相同。优先消除同一业务决策的多份实现；两个暂时相似、未来变化方向不同的功能可以保留独立实现并简述原因。
- 工具会过滤过短或结构过小的候选，部分语言构造也不参与比较；报告范围和排除项。退出 0 只是生成报告成功，有候选也可能退出 0。
- 合并后运行相关行为回归。不能为降低重复分数引入难懂的通用框架，或换变量名掩盖重复。
