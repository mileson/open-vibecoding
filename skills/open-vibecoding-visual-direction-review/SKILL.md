# 视觉方向评审

先拿到用户任务、关键动作和交互结构；视觉方向不能替代流程设计。对既有界面，先用同一张真实当前截图作为所有候选的参考，并保持品牌和平台视觉 DNA；冷启动则用明确的设计简报，不伪造修改前图。

- 确需探索时生成三个有实质差异的方向，变化应落在信息层级、布局、导航、任务路径或空间构图，不只是换颜色。每个方向说清适用场景、记忆点与风险。
- 使用当前宿主可用的原生生图能力；不要默认调用用户自有付费 API。素材像素合同与反模板化检查按 `$open-vibecoding-frontend-design` 的相关部分处理。
- 候选图是提案，不是已实现界面。生成多个候选后主动用 `design-review` 同时保存完整原图与编号拼图到项目根目录 `design/<scene>/vNNN/`，直接嵌入返回的 `chatEmbed` 供用户评审，不等用户再提醒拼图；不要让生图模型重画原图来拼图。新一轮生成新版本，不覆盖历史。调用方法见 [评审资产工具](references/design-review.md)。
- 只有用户明确选定后才用 `design-review select` 将所选原图标记 `final`，更新当前选定索引；拼图不能作为最终原图。用户未选择时可以明确说明可逆默认方向，但不能把它标为 final。
- 用户选择后把交互约束交给 `$open-vibecoding-interaction-design`，实现与视觉验收交给 `$open-vibecoding-frontend-design`。

用户已给出明确效果图时优先忠实实现；按钮、间距、颜色等局部调整无需三方向评审，但仍按风险保留必要的前后视觉证据。
