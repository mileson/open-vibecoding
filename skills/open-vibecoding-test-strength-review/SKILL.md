# 检查测试是否真的有效

内部测试能力，研发按需复用 [Mutator](https://github.com/unclebob/mutator)。先读取已安装的 `$open-vibecoding-code-quality` 下 `references/quality-tools.md`，确认安装、版本、覆盖率、运行副作用和源码安全。

1. 先通过目标范围的正常基线测试；确认测试不会产生真实扣费、消息发送等未授权动作，识别被链接的共享目录、外部系统与旧运行残留。
2. 用已核实环境执行 `python -m mutator --scan <目标文件>` 估计变异范围，确认没有意外全仓扫描。
3. 限定相关文件、现有有效覆盖率与相关测试命令，串行执行 `python -m mutator --max-workers 1 --use-existing-coverage --test-command '<已验证的测试命令>' <目标文件>`。默认不使用全量重跑或跳过覆盖率的选项。
4. 对重要未覆盖行为补测试；对存活变异判断是断言缺失、用例未触及，还是逻辑等价。等价变异保留原因，不能为了“全杀死”添加无意义断言或改坏正确行为。
5. 单独识别超时、编译失败、环境故障与行为断言失败：上游会将部分此类情况计为 killed，不能全部视为测试有效的证据。检查未执行数量和零变异情况，避免空报告通过。
6. 查明死代码没有合法入口、反射使用或兼容用途后，在授权范围内清理。结束确认源码状态、工作目录与本任务运行资源；发现不明残留先停下核对，不自动恢复或覆盖用户文件。

报告实际执行数、存活与未覆盖范围、异常与等价变异、正常基线结果；退出码分别解释。该结果补充真实用户业务验证，不能代替它。不要求普通小改动全仓运行变异测试。
