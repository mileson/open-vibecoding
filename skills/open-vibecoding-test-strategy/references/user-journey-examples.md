# 业务场景示例

这些例子帮助 Agent 理解验证目标，不是固定触发词或必须全部执行的清单。先采用用户明确要求和产品已有行为作为预期依据；有真正歧义时再询问，不把当前错误实现当正确答案。

| 用户要解决的事 | 实际怎么检查 | 什么才算得到结果 |
|---|---|---|
| 修改字幕后继续生成成片 | 从作品记录进入，修改字幕，继续生成，再打开最终视频 | 修改确实出现在最终视频，相关画面与声音正常；不是只看到生成成功 |
| 配置功能后外层仍显示未开启 | 从外层进入配置，完成保存，返回外层，必要时重新打开 | 内外状态与真实可用性一致；不是预设接口返回成功 |
| A 对话运行时，用户还要操作 B | 向 A 发起任务，切到 B 操作，再返回 A | B 不被无关阻塞，A 的输入与进度保留，完成结果归属正确 |
| 用户购买会员后仍不能用 | 在授权的支付测试环境完成购买，读取权益，再使用原先受限功能 | 购买、权益、实际功能连起来；同时说明是沙箱还是生产验证 |
| 用户编辑到一半切走又回来 | 在对应设备编辑、切后台、返回并继续 | 未提交内容和当前步骤符合产品约定；桌面网页不能证明手机后台行为 |
| 更新工具后要继续使用 | 在授权测试安装中按原安装方式更新，再运行原来的关键操作 | 更新后仍可使用；不把用户的日常安装擅自搬走或重装来造测试环境 |

## 老问题怎样成为复测样本

例如“退出字幕页后继续生成卡住”：保留可复现的脱敏草稿和预期“先出现确认入口，再继续生成”。修复后检查这条真实路径；以后涉及恢复流程的改动再复测。若数据不能安全保存，用不含个人信息的等价输入，不复制完整用户账号、对话或媒体。

基准来自用户要求、业务规则或已审核结果，不是程序当下输出什么就认可什么。结果变化先判断是否合理，再更新基准。对 AI 文案和媒体明确必要内容、禁止问题与可接受差异，避免把正常变化误判为失败。

## 简短汇报示例

“在测试版中，使用测试账号，从作品记录修改字幕后继续生成；已打开最终视频，修改生效。生成服务使用了回放数据，所以真实服务调用尚未验证。没有操作生产账号。”

不需要照抄格式，也不强制创建文件。没有真实服务证据时，不能省略最后的限制。

## 参考与边界

- [Playwright 测试建议](https://playwright.dev/docs/best-practices)：关注用户可见行为、测试隔离、可控测试数据；不可控第三方依赖可以模拟，但不能由此推断真实第三方链路已通过。
- [Playwright 视觉比较](https://playwright.dev/docs/test-snapshots)：提供基准比较能力，环境差异会影响截图。更新基准是技术操作，不等于业务批准新结果。
