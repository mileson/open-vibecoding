# 真实用户操作优先验证

属于 Open VibeCoding 测试模块，统一使用新版 Skill 入口。Agent 自主理解任务、安排测试；本指南提醒如何证明用户的事情确实办成，不接管思考方式，不用固定关键词或正则匹配场景。

## 先问用户最终要得到什么

涉及用户可操作的功能时，优先在运行中的产品里，以测试用户身份，从真实入口完成本次改动影响的业务流程，并检查最终结果。工具代替人点击、输入不是伪造业务结果；把接口或结果预设为成功则是模拟，不能混称真实链路验证。

以本次任务为边界，不要求每次把整个产品跑一遍。纯文档、内部局部逻辑或无界面的工具不为形式强开浏览器，选择对应的实际消费入口和结果验证。轻量视觉调整检查相关页面状态，不升级为全产品回归。

## 验收关注的优先级

1. **用户能否办成整件事**：从入口完成关键路径，检查保存后的内容、实际权益、导出文件或其他最终结果；按钮可点、成功提示、构建成功和单张截图不能替代结果验证。
2. **环节是否接得上**：核对上一步的真实结果是否被下一步正确使用，尤其关注权限、支付、跨服务、保存再打开以及恢复任务。
3. **典型案例是否仍然正确**：用脱敏的历史故障输入、代表性真实样本和已确认结果复测。黄金样本可用于完整流程或环节验证，不是每次必加的独立层；不得仅为了通过测试更新基准。AI/媒体结果按关键内容、允许差异或质量标准判断，不机械要求逐字或逐像素相同。
4. **关键局部规则是否准确**：金额、权限、额度、重复执行、边界计算等适合用快速小测试补充。不为每个函数凑测试，不按数量、覆盖率数字或固定比例判断业务已经可用，也不因此删除已有有效测试。

这是证据价值的考虑顺序，不是固定执行顺序。开发中可以先跑低成本局部检查；它通过后仍不能代替本次需要的真实用户路径。

## 按当前可用能力选择工具

- Codex、Claude 等客户端实际提供可安全使用的 Computer Use 时，优先通过它亲自操作目标浏览器或应用。先确认工具可调用、窗口归属、运行版本和账号角色；不能仅凭客户端名称推断能力存在。
- 网页的稳定重复回归可使用 Playwright 等现有工具；Computer Use 不可用或无法安全控制目标时，也可用实际可用的网页自动化完成验证。说明采用的方式，不把脚本执行冒充 Computer Use 操作。
- 涉及原生应用、系统权限、后台切换或平台差异时，在对应平台验证。网页、模拟响应或模拟器不能代替它们未覆盖的真机行为。微信小程序按宿主要求使用实际可用的专用验证能力。
- 不为普通验收强制新增依赖、启动浏览器或派发 subagent。需要独立产品视角时组合 `$open-vibecoding-ui-interaction-review`；用户要求修复再组合 `$open-vibecoding-ui-review-and-repair`。Reviewer 自身也要核实工具是否可用，同一界面同一时刻只由一个 Agent 控制。

## 真实场景不等于默认操作生产环境

优先复用可控的测试环境、测试账号和有代表性的数据，覆盖本次相关的正常路径、必要失败与恢复场景。生产验证须有相应授权和明确范围；真实扣费、消息发送、删除业务数据等不能因“要测完整”而自动获准。测试账号也不代表不会影响真实系统。

外部服务不可控、成本高或故障难以安全制造时，可使用沙箱、回放或模拟响应补充测试；明确被替代的环节及结论边界。支付沙箱成功不等于真实生产扣款成功，模拟会员生效不等于实际购买链路已验证。关键真实环节缺失时，报告未验证，不通过放宽断言或伪造结果宣称完成。

复用当前任务环境，重资源默认串行；失败先读现有日志，不反复重启、堆开模拟器或清全部缓存。结束只清理本任务创建且不再需要的资源。

## 如何收口

用业务语言说明：在哪个环境和版本、以什么角色、实际做了什么、观察到什么结果、哪些环节用了模拟、哪些仍未验证。只保留能支持结论的必要证据，区分通过、失败、未运行与无法验证；未知不等于失败或通过。

界面视觉审查必须落实 `$open-vibecoding-visual-evidence-delivery`：最终回复嵌入本轮实际截图；有确认参考时展示参考与实际结果，无参考时展示最终实际界面。仅保存图片、给路径或文字说通过不算交付；无法取图时标记视觉未验证。媒体从最终产物复测；截图与亲自点击均不能替代后台数据或成片质量验证。不要求创建 tasks、evidence-plan、Markdown/HTML 测试报告；只有用户或复杂审查确实需要时才制作长期材料。

需要把这些原则转成具体操作时读 [业务场景示例](references/user-journey-examples.md)。
