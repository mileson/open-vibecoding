# 竞品分析

先明确要支持的产品决策，再选可比对象：直接竞品、间接替代和用户自己的手工流程可以同台比较，但必须注明类别。不要为凑数量扩大样本。

1. 用相同任务和条件观察各方案的入口、关键路径、状态反馈、失败恢复、成本与限制；区分实测、官方声明、第三方评价和推断。
2. 给动态信息附核验日期和来源。公开仓库架构与第三方技术能力遵守 `$open-vibecoding-benchmark-router` 的证据规则；`benchmark` CLI 只管理参考来源，不代替产品判断。
3. 解释差异为什么可能影响目标用户，而不只列功能有无。指出适用前提、可迁移原则、不可照搬的品牌或系统约束。
4. 输出少量能改变决策的发现、证据缺口和下一步验证；用户未要求时不生成固定竞品报告文件或 PRD。

若问题实际是“用户为什么不用我们的功能”，先用 `$open-vibecoding-product-diagnosis`；若已明确交互改动，再用 `$open-vibecoding-interaction-design`。
