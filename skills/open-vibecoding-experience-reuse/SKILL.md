# 经验复用

先定位当前问题与已有经验的共同条件，再核对来源、适用版本、验证结果和失效边界。历史记录是线索，不是高于当前代码和实测的事实。

- 仅提取会改变本次判断的规则、失败模式或检查点；与当前场景不匹配的经验要明确排除。
- 已验证且反复有价值的问题可按现有 `quality` 或 `grow` 能力形成候选；晋级为共享规则遵守原有审核，不由一次任务自动推广。
- 用户要求系统性复盘或长期阅读材料时再使用 `$open-vibecoding-learning-review`；日常任务不制作学习包。
- 将复用效果与新证据反馈到本次工作，避免旧结论压过当前事实。
