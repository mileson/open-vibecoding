# 资源精简与生命周期管理

用户没有特殊说明时，以正常运行、必要验证与数据安全为约束，采用最小足够的资源方案。主动考虑磁盘、内存、CPU/GPU、网络、磁盘I/O和持续维护成本，不默认无限资源，不通过过度副本或重复环境换取少量便利。按实际任务理解场景，不按固定词派发，也不要求每个任务新增资源计划或报告。

## 创建前与使用中

- 先查本任务与目标环境已有的服务、进程、窗口、模拟器、容器、下载和构建缓存；能安全复用就复用。共享机器先核对项目归属，不能为本项目操作影响其他项目。
- 选满足目标的最小工具和环境组合。限制重任务并发，优先串行复用，不为失败重试堆开同类实例。复杂基础设施、多份相同依赖、重复模型或独立服务需有实际需求，不因“以后可能用”提前部署。
- 会持续增长的缓存、日志、临时文件、历史镜像与中间产物，要结合容量、重建成本、使用频率和运行要求确定保留边界或收尾时机。不无限保留，也不每次机械清空有效缓存；不统一规定容量、天数、告警百分比或服务数量。
- 对频繁执行的构建、发布和媒体处理，主动检查现有脚本是否遗漏失败产物处理与成功后收尾；在用户已授权实现范围内补齐最小必要逻辑。新调度、宿主级配置或共享清理策略属于额外范围，不因一次清理自动建立。

## 保留什么，处理什么

先区分运行必需资源、用户或业务数据、必要诊断/验收证据，以及可重建的闲置资源。可重建只描述性质，不代表已经获准删除，也不证明现在没有引用。

- 默认不为“保险”额外堆积源码备份、历史发布包、回滚目录/镜像、同一内容的多份副本。已有明确备份、恢复目标、审计或保留要求时按其执行；不能从“精简”推导删除数据库备份或降低已约定的恢复能力。
- 本任务创建且已不再需要的临时进程、窗口、环境和中间产物主动收尾。已有资源只在用户明确接管或项目清理授权范围内处理；对象不明、权限不明或不可逆风险较高时先说明，不把分析请求升级为清理。
- 处理前核对具体路径/对象、实际引用、挂载、并发构建和共享关系。镜像没有标签、容器已停止、文件较旧或工具标记“可回收”都不足以单独判定可删除。不硬编码通用一键删除命令，不采用全盘或全宿主无范围清理。
- 保护运行版本、用户上传、数据库、数据卷、必要配置、待处理任务和唯一副本；离线运行、重建所需依赖或无法重新取得的产物同样需要识别。远端已有文件时核实完整性、可访问性和运行依赖后，才能判断本地是否冗余。
- 缓存清理可能增加后续下载、构建时间与费用，需与节省空间一起权衡。共享层、逻辑可回收量与真实释放量分别判断，不把列表大小直接相加当作释放承诺。

## 收尾与验证

创建环境前后及收尾时做最小必要的运行态检查；仅检查不创建环境的任务无需额外启动服务。实际处理后读回资源占用及相关业务健康，检查本轮产物、服务和必要恢复路径仍可用。前后使用可比较的口径，说明释放量、保留原因及未验证部分；删除命令成功不等于业务无影响。

验证请求不自动授权清理。无法安全检查依赖时保留对象并说明风险，不为完成清理数字删除更多内容。失败先分析现有日志和状态，不反复重启或清全部缓存。

在研发、工具选择、重构与验收中按需复用；方法的业务示例见 [场景示例](references/business-scenarios.md)。用户计费次数和套餐权益由独立资源权益能力维护，两者不混用。普通任务只做适用提醒，不接管 Agent 拆解方式，不生成强制流程文档。
