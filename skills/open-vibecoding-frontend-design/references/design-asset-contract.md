# 设计资产合同

## 目标

让“做界面”先有事实源和资产源，而不是先堆样式。

## 最小合同

涉及素材、真实内容或设计参考时，先明确相关信息是否存在；只有后续比较或复用确有需要时才写入 active 文件：

| 维度 | 需要什么 | 缺失时怎么办 |
| --- | --- | --- |
| 产品事实 | 产品名、版本、发布时间、关键规格、价格、引用数据 | 核实后使用；跨轮复用时可记入 `facts-sheet.md`，未知标为待确认 |
| 品牌资产 | logo、品牌色、字体、口号、icon 风格 | 优先查现有项目；确需追溯时记入 `asset-spec.md` |
| 内容资产 | 产品图、场景图、摄影图、插图、图表、馆藏图、案例图 | 判断是否为页面成立前提；必要时记录来源和降级方案 |
| 参考资产 | 用户给的效果图、设计稿、参考截图、参考站点局部 | 需要实现对比时保存，注明是否为主参考源 |
| 审美资产 | 字体组合、色彩角色、动效节奏、背景/表面、纹理、构图记忆点 | 明确审美主张，不临场套通用 AI 风格 |
| 布局资产 | 页面骨架 | 先复用项目结构；内置 skeleton 仅在适合时选用 |
| 组件资产 | 当前任务需要的结构块 | 优先复用项目组件；缺口再设计 |

## 禁止行为

- 不声明当前 `task-scope` 就聚合读取 `.open-vibecoding/design/active/` 的历史子目录，或让旧任务的材质/风格静默成为新任务默认方向。
- 只凭参考截图判断头像源像素是圆角卡片、透明 cutout 还是 full-bleed tile；必须检查原始素材、消费组件/CSS，或在当前任务的素材说明中显式锁定。
- 把 UI 容器的圆角、边框或阴影默认烘焙进源位图。
- 对 `opaque-full-bleed-tile` 生成图片内圆角卡片、白色外边或透明角；对 `transparent-cutout` 留下不透明背景角；两种模式验证互相替代。

- 没核实事实就直接写产品页。
- 没拿到真实内容图却先做内容型页面的大面积版式。
- 用户已经给了效果图，却还把样式库默认风格当成更高优先级。
- 一边实现一边临时发明主题、组件和布局体系。
- 没有品牌或参考图约束时，默认使用紫白渐变、蓝紫光晕、玻璃卡、白底卡片堆叠或通用 SaaS hero。
- 把 Inter、Roboto、Arial 或 system-ui 当成默认审美答案；如果确实需要中性字体，要说明它服务于密度、系统一致性或可访问性。
- 用动效、渐变、纹理、阴影或装饰覆盖事实、素材、任务路径缺口。

## 完成判断

- 用户给的参考图在实现中被正确使用；候选图与真实实现没有混称。
- 头像和单物件位图的 `rendering-mode`、消费组件证据与四角/边缘验证一致。
- 事实、素材和审美选择能支撑当前页面；没有通用 AI 模板味或用装饰掩盖内容缺口。
- 需要跨轮复核的参考与视觉证据才保存到对应文件，并标明当前任务；历史任务只通过显式引用进入当前方向。
